### пояснение: что такое scope-ассерционы

В Sublime есть штатный автотест подсветки: файл-фикстура с директивой
`// SYNTAX TEST "Packages/QSP/qsp.sublime-syntax"` в первой строке. Обычный
комментарий языка внутри такого файла может содержать утверждения о том, КАКОЙ
scope синтаксис реально выдал для конкретного символа. В QSP-файле комментарий
начинается с `!`, поэтому рабочие формы такие:

- `! <- meta.begin_cycle.qsp` — «scope под колонкой в СТРОКЕ ВЫШЕ = …»;
- `! ^^^ keyword.control.cycle.begin.qsp` — то же, но для символа над каждым `^` (блоком несколько символов подряд);
- `! ^^ constant.numeric.qsp -invalid.illegal.qsp` — можно дополнительно указать `-scope`: этого scope быть НЕ должно;
- `! ^^^ scope |meta.block` — через `|` проверяется meta-скоуп (стеки блоков), а не только текст-скоуп;
- `! ^^^ scope ! <-- поясняющий текст` — всё после `! <--` игнорируется тестом.

(В туториалах часто встречается форма `# <- …` / `## ^^^ …` — это те же
утверждения для файлов с другим префиксом комментария: JSON, Markdown и т.п.)

Запуск: файл открывается в Sublime, `Tools → Build With… → Syntax Test` (нужен
пакет «Package Development», включается в Settings — Package Development: Yes).
Несоответствие — красный список в build-панели, без глаз и скриншотов.

ВАЖНО (уточнено 2026-10-27, я был неточен в прошлый раз): в
`QSP.sublime-package/syntax_test_qsp.qsps` сейчас НУЛЬ утверждений — там только
директива `// SYNTAX TEST` в первой строке и локации с кодом для визуальной
проверки. То есть файл выглядит как автотест, но им не является (и никогда им
не был — утверждений не было даже для ранних Фаз, я называл их «тестами»
неверно). Предложение: дописать в него `! <- / ! ^^^`-утверждения для кейсов
Фаз 7/8/9 (многострочные скобки в заголовках act/if/loop/elseif, `loop` со
скобкой ДО `while`, `--` внутри незакрытой `(`/`[`/`{`), чтобы регрессия
ловилась запуском, а не взглядом. Фикстуры в `_examples/example_syntax/`
остаются как «что посмотреть глазами», но именно эти кейсы продублируются
проверяемо.

Цена вопроса (почему это отдельная задача, а не «подчистить за 5 минут»):
утверждения привязаны к КОЛОНКАМ, а фикстуры Фаз 7/8/9 многострочные — значит
для каждой проверки надо аккуратно выставить `^` под нужный токен и зафиксировать
ожидание «блок открыт / не открыт» через `meta.*` + `-invalid.illegal.qsp`. Это
самостоятельная работа, её смысл появляется только если мы собираемся гонять
тест регулярно (например, перед каждым релизом пакета).
