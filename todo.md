### пояснение: что такое scope-ассерционы

В Sublime есть штатный автотест подсветки: файл-фикстура с директивой
`// SYNTAX TEST "Packages/QSP/qsp.sublime-syntax"` в первой строке. Обычный
комментарий языка внутри такого файла может содержать утверждения о том, КАКОЙ
scope синтаксис реально выдал для конкретного символа. Утверждения пишутся в
строках, начинающихся с `//` — это ФИКСИРОВАННЫЙ префикс движка, он НЕ зависит
от комментария языка. Проверено 2026-10-29: `! ^^^ scope` (QSP-комментарий) и
«голые» строки `^^^ scope` движок НЕ видит — файл рапортует `Success: 0 assertions`,
то есть молча ничего не проверяет. Рабочие формы такие:

- `// <- scope` — ОДНА позиция: первый непробельный символ строки выше (единственный способ утверждать про колонку 0: `//` занимает колонки 0–1);
- `// ^^^ scope` — по символу над каждой `^`; колонки АБСОЛЮТНЫЕ: `//` занимает колонки 0–1, поэтому для символа в колонке N нужно N−2 пробела после `//` (для N=4 — `//  ^`). Ошибка на один символ — самый частый провал, чекер теперь ловит каретки НА ПРОБЕЛЕ;
- `// ^^ constant.numeric.qsp -invalid.illegal.qsp` — можно дополнительно указать `-scope`: этого scope быть НЕ должно;
- ПОРЯДОК SCOPE ЗНАЧИМ (выяснено 2026-10-29): движок ищет ожидаемые scope как УПОРЯДОЧЕННУЮ подпоследовательность стека (снаружи внутрь). `keyword.control.conditional.begin.qsp meta.begin_condition.qsp` провалится, если факт — `meta.begin_condition.qsp keyword.control.conditional.begin.qsp`; лишние scope стека (`source.qsp`, `meta.location.qsp`, `avs_*`) не мешают. Писать в том порядке, в каком их печатает build-панель;

Блок подряд идущих ассертов относится к ПОСЛЕДНЕЙ не-ассерт-строке.

Запуск: файл открывается в Sublime, `Tools → Build With… → Syntax Test` (нужен
пакет «Package Development», включается в Settings — Package Development: Yes).
Несоответствие — красный список в build-панели, без глаз и скриншотов.
