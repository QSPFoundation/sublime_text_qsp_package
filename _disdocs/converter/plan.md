# План рефакторинга `qSpy/converter`

Аудит проведён 2026-11-03. Все findings ниже подтверждены чтением кода и/или
эмпирическими прогонами на живых фикстурах (`_examples/examples_qsp_to_qsps/ukuzya_txt2gam.qsps`).

## 0. Архитектура модуля (карта для рефакторинга)

Конвейер: `.qsp` (шифр ±5) ⇄ `.qsps` (исходник) ⇄ сборка `.qsp`.

| Файл                                                                  | Ответственность                                                                                                               |
| --------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| `tps.py`                                                              | Type-алиасы и TypedDict (`Action`, `QspLocation`, `LocFindMode`, `BaseFindMode`, …)                                           |
| `tools.py`                                                            | `parse_string` (трекинг кавычек/скобок по строке), `del_first_pref` (снятие общего отступа), `QSP_CODREMOV = 5`               |
| `qsps_file.py`                                                        | `QspsFile` — сущность qsps-файла, сплит строк на локации (`split_to_locations`)                                               |
| `qsp_location.py`                                                     | `QspsLoc` — локация: выделение BASE-блока (`_extract_base`), разбор base (`split_base`), обратная сборка qsps (`get_sources`) |
| `base_scanner.py` / `base_parser.py` / `base_stmt.py` / `base_int.py` | Лексор → парсер → AST → интерпретатор **только BASE-блока** (описание `*P` + `ACT…END`)                                       |
| `base_tokens.py`                                                      | `BaseToken`/`BaseTokenType` для base-подсистемы                                                                               |
| `base_printer.py`                                                     | AST-дамп base-подсистемы в dict-нотацию — **никем не используется**                                                           |
| `qsp_to_qsps.py`                                                      | `QspToQspsBuiltinConv` — чтение/декод `.qsp` (подбор encoding), сплит на локации, генерация qsps                              |
| `converters.py`                                                       | `QspsToQspBuiltinConv` (qsps→qsp, шифрование), `QspsToQspOuterConv` (обёртка txt2gam)                                         |
| `qsp_splitter.py`                                                     | `QspSplitter` (раздача локаций по файлам по `.qproj`), `FinderSplitter` (обход папки)                                         |

Внешние потребители: `QSP.py` (команды), `builder.py` (сборка через `QspsToQspBuiltinConv`/
`QspsToQspOuterConv` + `handle_temp_file`), `workspace.py` (`QspsFile.get_loc_symbols`), `moduleqsp.py`.

## 1. Логические ошибки (подтверждено)

### B1. Поведение (не баг): `--` в колонке 0 вне кавычек закрывает локацию

`qsps_file.py`, `LOCATION_END = re.compile(r'^\-\-(.*)$')` матчит любую строку с `--` в колонке 0,
**но только при пустом `mode['quote']`** — трекинг кавычек/скобок через `parse_string` реально
защищает `--` внутри строк (проверено N1: `--` внутри незакрытой кавычки локацию не закрывает).
`--`-комментарий в колонке 0 вне кавычек закрывает локацию (проверено N2) — это **соответствует
официальному правилу формата QSP** (память «Границы локаций QSP: колонка 0, конец только `--»,
txt2gam делает так же). Т.е. код локации после такого комментария мёртв и в самом движке —
потери данных нет, это контракт формата.
**Решение (Q1):** матчинг имени локации в `LOCATION_END` — вопрос не фикса, а **диагностики**:
guard-предупреждение о «подозрительном закрытии» (по аналогии `wrongclose_locend` в подсветке),
чтобы пользователь видел случайный `--` в колонке 0. Реальный соседний дефект — B14/N4.

### B2. Имя локации не тримится от хвостовых пробелов — **ФИКС ПРИМЕНЁН**

`qsps_file.py`: `match.group(1).replace('\r', '')` убирал только `\r`; хвостовой `' '`,
`\f`, `\v` оставались в имени (проверено: `'# loc1 \n'` → имя `'loc1 '`).
Порочные последствия: не совпадает маппинг `qproj_data[loc_name]` в `QspSplitter`,
кривые пути файлов, `-- 'loc1 ' ---` в `QspsLoc.get_sources`.
**Решение (2026-11-03):** `.rstrip()` при извлечении имени (`qsps_file.py`, строка 86) —
снимает все хвостовые пробельные символы включая `\r`/`\f`/`\v`/`' '`. Проверено прогоном.

### B3. `QspsLoc._extract_base` — незакрытый `! BASE` дублирует код — **ФИКС ПРИМЕНЁН**

Маркеры: `_BASE_OPEN = ^! BASE$`, `_BASE_CLOSE = ^! END BASE$`. Если `! BASE` открыт и не закрыт:
`end` остаётся `-1`, ветка `start != end` берёт `_base_code = _code[start+1:-1]` и
`_run_on_visit = _code[0:start] + _code[0:]` — **весь код, включая base, попадает в run_on_visit**
(проверено, дублирование). Плюс частный случай `start == 0 and end == -1` даёт пустой срез.
**Решение (Q3, 2026-11-03):** salvaged-разбор, не фатальная ошибка: `! BASE` не закрыт →
base не выделяется (`_base_code` пуст), **весь код локации уходит в `run_on_visit`** (контракт
задокументирован пользователем в todo.md Notes), в консоль — сообщение
`Незакрытый блок "! BASE" в локации "<имя>"`. Проверено прогоном: дублирование устранено,
сообщение печатается, корректный/отсутствующий/«в кавычке» BASE не затронуты.

### B4. `QspsLoc.get_sources` — IndexError на пустом `run_on_visit` — **ФИКС ПРИМЕНЁН**

`self._run_on_visit[-1][-1]` падает, если у локации только BASE-блок без кода (проверено).
Также `'\n' if ... else ''` вставляет переводную строку **перед** `-- name ---` вместо
настоящего разделителя — формат выходного qsps сомнительный (Q4).
**Решение (2026-11-03, Q4 закрыт):** `qsps_lines.extend(self._run_on_visit)`; затем
`if self._run_on_visit and self._run_on_visit[-1][-1] != '\n': qsps_lines.append('\n')`
(защита пустого + явный терминатор строки вместо `\n`-префикса); затем
`qsps_lines.append(f'-- {name} ' + '-'*33 + '\n')` — маркер как законченная строка.
Пустая строка ниже `--` не добавляется (вариант A, по эталону: пустая строка перед `--` не
нужна, одна локация на файл в splitter). Проверено прогоном: пустой / terminated / без-`\n` run_on_visit.

### B5. `base_parser._braces` — отсутствие `continue` после вложенных braces — **ФИКС ПРИМЕНЁН**

```python
if self._check_type(tt.LEFT_BRACE):
    chain.append(self._braces())
chain.append(stm.Literal(self._curtok))   # <— выполняет всегда
self._eat_tokens(1)
```

После возврата из рекурсии внешний цикл **немедленно** добавляет текущий токен как Literal
и поглощает его — т.е. `RIGHT_BRACE` вложенных скобок съедается как литерал, внешняя скобка
не закрывается, «теряется» `}` и всё, что дальше (проверено на `! {a{b}c}`).
**Фикс:** `continue` после `chain.append(self._braces())`. — применён (`base_parser._braces`);
пин B5 в `_converter_roundtrip_test_.py` (вложенные `{a{b}c}` доходят до int-проверки, не `EOF in braces`).

### B6. `base_parser._extract_line(*pop)` — параметр `pop` игнорируется — **ФИКС ПРИМЕНЁН**

Тело вообще не использует `*pop`; в `_loop` вызывается `self._extract_line(tt.THEN)` —
аргумент-обещание не реализован. Пограничный риск: catch-all `_statement() → _literal()`
поглощает любой токен, **включая EOF** (`_eat_tokens` не защищён), дальше
`self._curtok = self._tokens[N]` → IndexError, либо бесконечный цикл, если `_statement`
не продвинул курсор (проверено: прямой краш недостижим на реальных входах, но механизм реален).
**Фикс:** `pop` реализован (стоп-токены, не поглощаются); `_literal` бросает `ParserError`
на EOF. Пины B6 (loop-in-base доходит до `visit_loop`) и B7-ParserError в roundtrip-тесте.

### B7. `base_int` — ошибки «глохнут» — **ФИКС ПРИМЕНЁН**

- `visit_print_text_stmt`: `raise RuntimeError(...)` вместо `RuntimeIntError` (строка 49) —
  этот единичный случай не ловится в `run()` и уронит весь `split_base()`.
- `run()` ловит `RuntimeIntError` и лишь `print` — локация собирается **с молча потерянным
  описанием/действиями**. Пользователь получает битый `.qsp` без кода ошибки.
- `visit_expression`: `output[1:-1]` при пустом `chain` вернёт `''` без ошибки; для
  non-Literal-узлов внутри `Expression` (`BaseToken` не имеет `.accept`) возможен `AttributeError`.
**Фикс:** `RuntimeError→RuntimeIntError` (стр.49); пустой `chain` в `visit_expression` —
ошибка; единый канал — `BaseInt.errors()` копит `RuntimeIntError`, `QspsLoc.split_base`
оборачивает скан/парс/прогон в `try/except (ParserError, RuntimeIntError)`, печатает с именем
локации (`Локация "<имя>": …`) и накапливает в `QspsLoc.base_errors()`. Сборка не падает.
Q10 решён (print — сток, наружу через accessor). Пины B7.

### B8. `base_scanner._base_scan` — мёртвая ветка и мусор в лексеме — **ФИКС ПРИМЕНЁН (частично)**

- Второй `elif c in (' ', '\t'):` (строка 115) недостижим — первый (`строка 90`) уже перехватил.
- В handler-состояниях (`_identifier_expect` и др.) на пробеле `_curlexeme.clear()` не
  происходит, но ветка `elif c in (' ', '\t')` не выполняется (иной хэндлер) — пробелы
  оседают в `_curlexeme`; хвост `'*P '` доходит до `_identifier_expect`. Сейчас маскируется,
  но это хрупкое «белое пятно» (см. Q5 — переписать сканер на нормальный pos-указатель).
- Регистр: `_KEYWORDS` нижний, lookup в `c in self._is_alnum`-ветке идёт без `.lower()`
  (`''.join(self._curlexeme)`), т.е. `ACT`/`IF`/`END` верхним регистром распознаются только
  чудом в `_identifier_expect` (там `.lower()` есть). Одиночная `P` после `*` даёт
  `IDENTIFIER 'P '` (проверено в токен-дампе). QSP-движок регистронезависим → разойдётся
  с подсветкой и реальными qsps-файлами (в фикстуре уukuzya встречается и `*P`, и `*p`).

### B9. `converters.QspsToQspBuiltinConv` — гонка в общем кэше — **ФИКС ПРИМЕНЁН (2026-11-04)**

Классовый `_char_cache: CharCache = {}` мутировался из `ThreadPoolExecutor(max_workers=32)`
в `encode_qsps_line`. Под GIL-CPython это был benign-race (идемпотентная запись), но формально
небезопасно, а под **free-threaded CPython 3.14** (среда Sublime Text) — уже настоящий data
race, и общий изменяемый dict к тому же душит масштабирование потоков.
**Решение (C3, 2026-11-04):** удалены `_char_cache` и `encode_char`; кодирование `qsps→qsp`
(чистый сдвиг кодовой точки на `-QSP_CODREMOV`) идёт через **неизменяемую** таблицу
`ENCODE_TABLE` (`dict ordinal→ordinal` на BMP, строится один раз при импорте) + `str.translate`.
Общего изменяемого состояния нет → гонки нет. `ThreadPoolExecutor` **оставлен** (3.14 реально
параллелит потоки); отказ от него и замер скорости — отдельной веткой позже. Golden roundtrip
— PASS (все снапшоты побайтово равны baseline).
**Осталось в B9 — ЗАКРЫТО (Фаза 4, п.4.1, 2026-11-04):**
- `*args` в `__init__` всех трёх конвертеров заменены на **именованные параметры**
  `conv_path:Path=''`, `conv_args:AppParam=''` (арность/индексация `args[0]/args[1]` убрана →
  нет `IndexError`-риска, контракт самодокументируем). Смысл имеют только у `QspsToQspOuterConv`;
  builtin принимает их ради единой сигнатуры построения и **намеренно игнорирует** (комментарий в
  коде). Позиционный вызов из `builder` не менялся → golden roundtrip PASS (снапшоты целы).
- `handle_temp_file()` builtin **не мёртвый** — вызывается из `builder._qsps_build` (debug-дамп при
  `save_temp_files=True`); в single-file пути `QSP.py` передаётся `save_temp_files=False` → корректно
  ничего не пишет. Оставлен как есть, кода не касался. Q8 (`base_printer`) тут ни при — та история
  про AST-дамп, не про temp-файлы.
- `conv_args` — **одна строка** (один argv-токен), собирается в `project._set_converter()`
  (`str(raw_converter[1])`, при converter-строке → `''`); зафиксировано комментарием в `builder`.
  Рассинхрон `OuterConv.convert_file` (пустой arg лепится в argv без `if`, в отличие от
  `convert_lines`) отнесён в **п.4.2 (B10)**.
_(Прежние формулировки «удалить/подключить рядом с Q8» и «никогда не вызывается» — неверны;
`handle_temp_file` вызывается в `builder._qsps_build`, не вызывается только в `convert_file`-пути.)_

### B10. `QspsToQspOuterConv` — **ФИКС ПРИМЕНЁН (Фаза 4, п.4.2, 2026-11-04)**

- `convert_file` всегда тащит `self._conv_args` (пустая строка `''` уходит в argv процесса).
- `convert_lines` возвращает `[]` с `# TODO: GameLines Return really need???` — contract
  базового класса не выполнен.
- `handle_temp_file` наоборот логике builtin: при `save_temp_files=False` удаляет файл,
  который мог не создаваться → `FileNotFoundError`.

**Решения (п.4.2, 2026-11-04).** Уточнение: живой путь outer — **только `convert_lines`** (builder);
`OuterConv.convert_file` в продукте **не вызывается нигде** (single-file команды `QSP.py` берут builtin).
- `convert_file`: пустой `conv_args` больше **не уходит в argv** (guard `if self._conv_args`, как в
  `convert_lines`) — рассинхрон веток устранён; реализация оставлена минимальной (только ради
  `@abstractmethod`), помечена комментарием «не живой путь». Не расширялась.
- `convert_lines`: возврат `[]` — **осознанно** (product — `.qsp` на диске, in-memory game-строк outer
  не производит; builder возврат игнорирует). TODO снят, поставлен комментарий-решение.
- `handle_temp_file`: добавлен guard `os.path.isfile` (нет `FileNotFoundError` при combos вне builder);
  «противоположность» builtin (тот пишет debug-дамп, outer удаляет рабочий temp) — НЕ баг, а следствие
  ролей; `save_temp_files` = «сохранять ли промежуточные файлы» читается одинаково. Задокументировано.
- **Отложено (в `todo.md`, секция Converter):** robustness `subprocess.run` (дренаж stdout, сбор stderr,
  проверка `returncode`) — вынесено из B10 в отдельную задачу на будущее.

Golden roundtrip — PASS (outer-путь тестом не гоняется, builtin не затронут) → поведение не изменилось.

- `split_qsp` не проверяет длину `_game_lines` (`IndexError` на файле < 4 строк);
  `_location_count` прочитан, но не валидируется против фактического числа локаций.
- `to_qsps`: локальная `_cl = ...convert_location` не используется; метод объявлен как
  возвращающий `List[QspsLine]`, но `convert_file` игнорирует возврат.
- `set_qsp_source_text` пишет в несуществующее поле `self.qsp_source_text` (не `_...`) —
  мёртвый метод с опечаткой.
- `read_from_file`: `ValidationFormatError` — подтип `ValueError`, а не `UnicodeDecodeError`;
  при ошибке заголовка на первой же кодировке цикл `except UnicodeDecodeError` его не ловит,
  исключение вылетает наружу (частично обходится, потому что `convert_file` ловит сам —
  но прямой вызов `read_from_file` из `QspSplitter._split_game` **не защищён**).
- cp1251 — последняя попытка и «всегда успешная» → UTF-8-файл без BOM молча прочитается
  как cp1251 (кракозябры без предупреждения).

### B12. Потеря данных на полном цикле `.qsp → .qsps → сборка → .qsp`

- `QspToQspsBuiltinConv.to_qsps` пишет служебные строки `«Число локаций: N»`, «Пароль: …»,
  которые `QspsFile.split_to_locations` нигде не парсит (это мусор до первой `#`).
- `QspsToQspBuiltinConv` записывает в заголовок литералы `'QSPGAME\n'`,
  `'SublimeText QSP-Package\n'` и пароль `'No'`, **не читая реальный пароль** из локации —
  roundtrip необратимо теряет пароль и line-2 заголовка.
- `save_to_file` пишет `utf-16le` **без BOM** — проверить, что движок/QuestSoftPlayer это
  принимает (Q6).

### B13. `qsp_splitter.py`

- `_split_game`/`_split_qsps` — ~90% дубликата (TODO автора в коде есть, строка 120).
- Защита от перезаписи: `count` ключуется базовым путём, а `os.path.isfile` проверяется для

### B14. `tools.parse_string` — слепые зоны (в т.ч. тихая потеря локаций) — **ФИКС ПРИМЕНЁН**

- Не понимает комментарии (`! ...`): `! он сказал "привет` открывает кавычку на весь остаток
  файла. Проверено (N4): из-за этого **ни одна локация не распознана** — `-- loc1 ---` не
  срабатывает при непустом `mode['quote']`, заголовок `# loc2` тоже игнорируется. Тихая потеря
  всего файла.
- При закрытии локации `mode['quote']` не очищался.
- Кавычки/апострофы внутри `{...}` не толкались на стек — `}` закрывала блок, «съедая»
  кавычку; `{"}"` давал рассинхрон.

**Принятые решения (2026-11-03):**

- Понимать `!`-комментарии в `parse_string` **не требуется** (контракт формата: движок тоже
  считает код после незакрытой кавычки мёртвым). Вместо этого — **принудительное закрытие
  открытой локации в конце файла** с console-сообщением `Неожиданный конец локации "<имя>", файл: <путь>` (`qsps_file.py`); тихая потеря больше невозможна, данные локации сохраняются.
- Стек `quote` очищается **при закрытии** локации (и при EOF-закрытии). При *открытии* очистка
  не нужна — проверено: вне локации `parse_string` не вызывается (ветка `pass`), стек при
  открытии всегда пуст.
- Модель слоёв исправлена: фигурные скобки внутри кавычек/апострофов — не учитываются,
  кавычки/апострофы внутри `{...}` — **учитываются**, `{` внутрь `{` — вложенно.
