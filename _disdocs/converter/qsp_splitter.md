# Разделитель `qsp_splitter`

Сплиттер разбивает один файл QSP на отдельные файлы-локации в формате qsps и раскладывает их по папкам согласно `.qproj`.

> формат TXT2GAM и qsps — это одно и то же: текстовый файл с особым форматом записи QSP-кода.

Модуль является частью пакета `converter`: `QSP.sublime-package/qSpy/converter/qsp_splitter.py`. Используется как подключаемый модуль.

## Импорт

`QspSplitter` и `FinderSplitter` экспортируются из пакета `qSpy.converter`. При запуске вне Sublime каталог `QSP` нужно добавить в `sys.path`:

```python
import sys, os
sys.path.insert(0, os.path.abspath('/Путь к папке пакета/QSP'))

from qSpy.converter import QspSplitter, FinderSplitter
```

## Классы

### `QspSplitter` — разбор одного файла

Конструктор принимает режим входа, а метод `split_file` — путь к файлу:

```python
splitter = QspSplitter(mode)
splitter.split_file(input_file, output_folder=None)
```

- `mode` — `'game'` (входной файл `.qsp`, бинарный QSP-Game) или `'txt'` (текстовый qsps-файл).
- `input_file` — путь к разбираемому файлу. Если файла нет, в консоль выводится ошибка `[400] ...` и разбор пропускается.
- `output_folder` — необязательная переопределённая папка результата. Если не задана, результат пишется **на месте** (in-place): создаётся папка с именем исходного файла рядом с ним.

Примеры:

```python
# .qsp → разобрать на локации in-place (папка tooloz/ создаётся рядом с tooloz.qsp)
QspSplitter('game').split_file('tooloz.qsp')

# qsps-файл → разобрать на локации и поместить в папку sources соседнюю текущей.
QspSplitter('txt').split_file('drive.qsps', '../sources/')
```

### `FinderSplitter` — обход папки и разбор всех найденных файлов

```python
finder = FinderSplitter(mode=('game', 'txt'), recursive=True, output_root=None)
finder.search_n_split(folder_path)
```

- `mode` — кортеж режимов, какие типы файлов обрабатывать (`'game'` — `.qsp`, `'txt'` — qsps).
- `recursive` — спускаться ли в подпапки (по умолчанию да).
- `output_root` — куда класть результат. По умолчанию `_src`, созданная **соседом** `folder_path` (на одном уровне с ней), с зеркалом дерева исходников внутри (`_src/<имя_папки>/...`). Если задать свой путь внутри `folder_path`, он исключается из обхода — то есть, если файлы там уже созданы, они не будут обработаны повторно.
- `search_n_split(folder_path)` — находит в папке все файлы-источники и для каждого вызывает `QspSplitter(...).split_file(...)`.

```python
# разобрать все .qsp и qsps-файлы в папке проекта, результат в соседний _src
FinderSplitter().search_n_split('my_project')

# разобрать все .qsp и qsps-файлы в папке проекта, результат во вложенный _src
FinderSplitter().search_n_split('my_project', './_src')
```

## Определяемые расширения

| режим             | расширения                               |
| ----------------- | ---------------------------------------- |
| `'game'` (`.qsp`) | `.qsp`                                   |
| `'txt'` (qsps)    | `.qsps`, `.qsp-txt`, `.txt-qsp`, `.qsrc` |

## Результат работы

Для каждого локационного файла:

- Каждая локация записывается отдельным файлом `<имя_локации>.qsps` (кодировка UTF-8). Первая строка файла — `QSP-Game <имя_локации>` и пустая строка, далее — код локации.
- Если рядом с исходником лежит одноимённый `.qproj`, локации раскладываются по подпапкам согласно карте из `.qproj`; иначе все файлы ложатся плоско в папку результата.
- **Перезапись исключена**: при коллизии имён берётся первый свободный путь с суффиксом `_1`, `_2`, … — переразбивка накапливает дубли, а не затирает файлы, так обеспечивается защита от случайной порчи проекта.
- Недопустимые символы в именах заменяются на `_`; зарезервированные Windows-имена (`CON`, `PRN`, `AUX`, `NUL`, `COM1`, `LPT1` и т.п., регистронезависимо) экранируются ведущим `_`.
