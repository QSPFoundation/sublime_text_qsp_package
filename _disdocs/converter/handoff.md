## Решения, уже принятые в ходе аудита
- **B3 исправлен (2026-11-03, вне порядка фаз, Q3 закрыт):** незакрытый `! BASE` —
  salvaged-разбор без фатальной ошибки: base не выделяется, весь код локации уходит в
  `run_on_visit` (без дублирования), в консоль — сообщение «Незакрытый блок "! BASE" в
  локации "<имя>"» (`qsp_location.py`, `_extract_base`). Проверено прогоном: закрытый/
  отсутствующий/«в кавычке» BASE не затронуты.
- **B14 исправлен (2026-11-03, вне порядка фаз):** комментарии в `parse_string` не
  обрабатываются (решение пользователя — контракт формата); вместо тихой потери —
  принудительное закрытие открытой локации на EOF с console-сообщением «Неожиданный конец
  локации "<имя>", файл: <путь>»; стек `quote` очищается при закрытии локации (при открытии
  не нужен — вне локации `parse_string` не вызывается); кавычки/апострофы внутри `{...}` теперь
  считаются слоями стека (фигурные скобки внутри кавычек — как раньше, игнорируются);
  тесты 9–12 в `_converter_tools_tests_.py`, регрессия N4 прогнана.
- Временные диагностические скрипты удалены (политика: одноразовые скрипты после
  завершения удаляются, опыт фиксируется в docs/памяти).
- Мёртвый код не оживляем — удаляем (память проекта), кроме `base_printer.py` —
  его судьба за Q8.
- `LOCATION_END` НЕ переделывается: закрытие по `--` в колонке 0 — контракт формата
  (перепроверено); матчинг имени — только как диагностический guard, ждёт Q1.
  Приоритет Фазы 2 сместился на B14 (тихая потеря локаций из-за кавычки в комментарии).
- Ограничение «однострочные ACT не поддерживаются» с внятным текстом ошибки —
  предварительно оставляем (Q9), ошибка не должна глохнуть (B7).
