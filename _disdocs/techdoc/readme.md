# Developer notes: пакет QSP для Sublime Text

Краткие заметки для разработки пакета. Пользовательское руководство — [README.md](../../README.md), план рефакторинга — [general_ref.md](../../general_ref.md), контекст передачи между чатами — [handoff.md](../../handoff.md).

## Состав пакета

- `QSP.py` — точка входа плагина ST: команды билда/конвертации/сплиттера, подсветка, автодополнение, workspace-листенеры.
- `qSpy/` — ядро логики:
  - `builder.py`, `project.py`, `moduleqsp.py` — сборка проекта по `qsp-project.json`;
  - `workspace.py` — индекс локаций/файлов по окнам (RAM-реестр, дисковый кэш v2, index.json, prune сирот);
  - `converter/` — qsps↔qsp, сплиттер, парсинг локаций;
  - `preprocessor/` — препроцессор директив (Off/On/Hard-off);
  - `tce/`, `tce_manager.py` — извлечение текстовых констант;
  - `vars_scanner.py` — on-demand скан локальных/глобальных переменных во вью;
  - `const.py`, `plugtypes.py`, `function.py` — константы, типы, утилиты.
- Ресурсы ST: `*.sublime-syntax`, `*.tmPreferences`, `*.sublime-build`, `QSP.sublime-settings`, `Default.sublime-commands`, `Main.sublime-menu`, `Default.sublime-keymap`, `Completions/`, `Snippets/`, `syntax_test_*`.

Подробная карта состава — [package-content.md](../../package-content.md).

## Workspace-кэш (кратко)

- Реестр `QSP_WORKSPACES: window.id() -> QspWorkspace`; доступ только через `for_window`/`peek_for_window` (с проверкой identity).
- `identity` = `normcase(abspath(.sublime-project))`; окно без `.sublime-project` — кэш не ведётся (только RAM).
- Дисковый кэш v2: `<sublime.cache_path()>/QSP/workspaces/<base>-<hash8>.json` + справочник `index.json`; атомарная запись `.tmp` + `os.replace`; флаш на `on_exit` — чистый IO без sublime-API.
- Инкрементальное обновление по mtime/size/md5; переименования файлов детектятся по общему md5.
- Полная документация: [QspWorkspace/structure.md](../QspWorkspace/structure.md).

## Настройки пакета

Дефолты поставляются в `QSP.sublime-settings`. Откройте `Preferences → Package Settings → QSP → Settings`: штатная команда ST `edit_settings` покажет дефолты слева и пользовательский файл `User/QSP.sublime-settings` справа. Существующее содержимое пользовательского файла сохраняется; если файла ещё нет, открывается пустой JSON-объект с курсором внутри. Редактируйте и сохраняйте правую часть, не меняя дефолты. Альтернативный доступ — `Preferences → Browse Packages…`, затем `User/QSP.sublime-settings`.

Пример пользовательских настроек (в непустом файле добавьте ключи к существующим):

```json
{
    "player_path": "",
    "converter_path": "",
    "prune_interval_days": 7,
    "orphan_max_age_days": 90
}
```

### Плеер и конвертер

- `player_path` и `converter_path` — строки, по умолчанию пустые. Пустой плеер не мешает сборке, но запуск требует настройки; пустой конвертер означает встроенный. `qsps_to_qsp` — явное имя встроенного конвертера, а не имя искомого файла.
- Приоритет: наличие ключа `player`/`converter` в `qsp-project.json` → соответствующая настройка пакета → пустой дефолт. Пустое проектное значение тоже является переопределением; `null`, числа, массивы вместо глобального пути и прочие нестроковые значения — ошибка. Проектный `converter` дополнительно принимает ровно две строки `[path, parameters]`; параметры передаются одним аргументом, не разбиваются по пробелам.
- Пути: абсолютный, с раскрытием `~`, либо имя из `PATH` процесса ST (может отличаться от терминала). Поиск имени использует непустые каталоги `PATH`, учитывает Windows `PATHEXT` и не добавляет текущий каталог неявно. Проектный относительный путь разрешается от каталога `qsp-project.json`; существующий локальный файл имеет приоритет над поиском имени через `PATH`. Относительные пути с каталогом в глобальных настройках отклоняются. Пробелы в путях допустимы без дополнительных кавычек; запуск остаётся списком аргументов без `shell=True`. На macOS нужен исполняемый файл внутри `.app/Contents/MacOS`, каталог `.app` не поддерживается.
- `QspBuildCommand` читает настройки при каждом вызове и передаёт их через `SchemeArgs`; `QspProject` не импортирует sublime. Валидируется только выбранное значение, поэтому корректный проектный override не зависит от ошибочного глобального.
- Ошибка конвертера делает схему непригодной для сборки, без тихого отката к встроенному; режим `--run` его не разрешает и не проверяет. Ошибка пути плеера хранится в `ProjectScheme.player_error` и выводится билдером только при запуске; `--build` продолжает работать. `OSError` при сборке/запуске выводится командой в консоль и прерывает её.
- `QSP_PROJECT_JSON` не содержит плеера/конвертера, чтобы новые quick-проекты наследовали настройки. Старые проекты не мигрируются: для наследования нужно удалить соответствующий ключ. Команда одиночной конвертации `QspsToQspCommand` остаётся встроенной.

Ручная проверка в ST на отдельном тестовом проекте:

1. Установите реальные `player_path`/`converter_path`, уберите проектные overrides, выполните Build и Build and Run; затем измените путь в User-настройках и повторите без перезапуска. Проверьте путь с пробелами, имя из PATH и `~` на соответствующей ОС.
2. При внешнем глобальном конвертере задайте проекту `"converter": "qsps_to_qsp"`: лог должен показать `BUILTIN mode`. Удаление ключа возвращает `OUTER mode`; пустой ключ вновь выбирает встроенный.
3. Проверьте проектные относительные пути плеера/конвертера. Неверный выбранный конвертер должен дать сообщение с именем параметра и путём до сборки; `Run` при этом должен оставаться доступен с корректным плеером и готовой игрой.
4. Задайте неверный плеер: Build должен завершиться, Run — вывести диагностику без запуска. Проверьте пустые настройки и создание quick-проекта без машинных путей.
5. Проверьте прежнюю команду `Tools → QSP tools → Converters → QSPS to game`; после проверки восстановите свои настройки.

### Очистка кэшей

- `prune_interval_days` — минимальный интервал между очистками кэшей-сирот в днях (по умолчанию 7).
- `orphan_max_age_days` — возраст кэша в днях с момента его последнего изменения (mtime), строго после которого допускается удаление (по умолчанию 90). Проект при этом должен отсутствовать и на диске, и в истории проектов ST; живые проекты не затрагиваются.
- Оба значения — положительные конечные числа, в том числе дробные. Ноль, отрицательные числа, строки, `true`/`false`, `null`, массивы и объекты отклоняются; используется дефолт соответствующего параметра.
- Изменения применяются при следующем вызове очистки без перезапуска ST. Очистка вызывается асинхронно при закрытии проекта/окна, а не по отдельному таймеру; сохранение настроек само по себе её не запускает.
- `force=True` у `prune_orphan_caches()` обходит только интервал, но не возраст кэша и не защиту живых проектов. Формат дискового кэша остаётся v2.

Ручная проверка меню и загрузки настроек в ST:

1. Откройте `Preferences → Package Settings → QSP → Settings`: дефолты должны быть слева, пользовательские настройки — справа. При первом открытии без пользовательского файла справа должен быть пустой JSON-объект; существующий файл не должен перезаписываться.
2. Задайте справа, например, `3` и `30`, сохраните и проверьте эффективные значения в консоли через `sublime.load_settings('QSP.sublime-settings').get('prune_interval_days')` и `.get('orphan_max_age_days')`.
3. Повторно выберите пункт меню: ST должен активировать уже открытое окно настроек, сохранив содержимое. Проверьте также, что пункты `Tools → QSP tools` остались доступны.
4. Измените значения, сохраните и повторите проверку без перезапуска; удаление пользовательских ключей должно вернуть дефолты 7/90. Затем восстановите нужные значения.

Этот сценарий не запускает очистку. Поведение очистки с невалидными значениями и граничными сроками проверяется smoke-стендом с fake-sublime на временных кэшах, не на реальном пользовательском кэше.

## Диагностика

- Палитра команд (`Ctrl+Shift+P`): `QSP: Show Workspace Cache` — открыть файл кэша активного окна; `QSP: Reset Workspace Cache` — удалить кэш и пересобрать индекс.
- Консоль ST (`Ctrl+~`): ошибки плагина/билдера выводятся через `qsp.function.write_error_log`.
- Дубликаты локаций — `QSP: Show Duplicate Locations`: попап со ссылками, переход открывает файл на строке заголовка локации.
- Подсветка переменных — on-demand `scan_vars(view)`, WS не используется.

## Проверка пакета

- Типы: `pyright QSP.sublime-package typings` из корня репо — strict-режим, `pyrightconfig.json` (pythonVersion 3.14, stub-ы `typings/` для sublime/sublime_plugin). На 2026-11-11 ядро и typings проходят без ошибок; по всему пакету остаётся ранее добавленная неопределённая `old` в `QspWorkspaceHandlers.on_load_project_async` (`QSP.py`, замер времени), не связанная с настройками инструментов. Запуск без путей захватывает также экспериментальные скрипты вне пакета.
- Настройки инструментов: `python -B _disdocs/techdoc/test_tool_settings.py` — unittest на временных проектах, fake-ST для команды, процессы замоканы. Проверяются приоритеты, пути/PATH, builtin, ошибки, повторное чтение и аргументы процессов; запуск реальных программ и нативный UI ST проверяются вручную. POSIX-проверка прав исполнения пропускается на Windows.
- Компиляция: `python -m py_compile QSP.sublime-package/QSP.py` (и изменённые файлы qSpy).
- Syntax-тесты ST: `syntax_test_*` в пакете, запуск встроенным тест-раннером Sublime Text.
- Ad-hoc тесты вне поставки: `_disdocs/tce/.tests/` (в пакет не входят, `.gitignore` — `**/.tests/`).
- Автотесты логики ядра (конвертер/билдер/WS): `python -B _disdocs/techdoc/test_core_logic.py` — unittest вне поставки пакета, fake-sublime для workspace, временные проекты для билдера, проверка кэша v2. Тесты не требуют Sublime Text. См. `general_ref.md` п.2.5.
- Smoke в ST после правок: build/run (`Ctrl+F5` / `Ctrl+Alt+Q` / `Ctrl+Alt+S`), конвертеры и сплиттеры (`Tools → QSP tools`), подсветка переменных, дубликаты локаций, автодополнение имён локаций, вставка новой локации между локациями (`new…`/`#` в начале строки → меню → Enter). После установки/обновления пакета — перезагрузка ST.

## Гигиена

- В пакете не должно быть `__pycache__/` и `*.pyc` (правила в `.gitignore`).
- Исходники и UI-строки — UTF-8; файлы `.qsp` — utf-16le (конвертер). Правки строковых ресурсов проверять визуально в ST.
- Тесты и ад-хок скрипты — вне дерева пакета (`_disdocs/...`).
