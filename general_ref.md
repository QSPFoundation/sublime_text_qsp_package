# План рефакторинга: `QSP.sublime-package` (Sublime Text)

## 1. Цель и границы
- **Цель:** повысить надёжность, сопровождаемость и предсказуемость пакета QSP для Sublime Text без изменения пользовательского поведения там, где это не требуется явно.
- **В рамках плана:** гигиена репозитория/пакета, устранение очевидных ошибок и мёртвого кода, консолидация техдолга, проработка белых пятен (незавершённые/неинтегрированные части), улучшение тестируемости и документации для разработки.
- **Вне рамок (отдельными задачами/эпиками):** крупные новые фичи анализатора, новая архитектура препроцессора/внешних скриптов, полный редизайн подсветки синтаксиса (кроме точечных исправлений), кроссплатформенная переработка плеера/путей «с нуля».

## 2. Карта проблем и белых пятен

### 2.1 Гигиена и состав пакета
| Проблема | Где | Влияние | Приоритет |
|---|---|---|---|
| Скомпилированные артефакты в исходниках/пакете (`__pycache__`, `*.pyc`, в т.ч. вложенные) | `QSP.sublime-package/**` | Шум в git, риск рассинхронизации, лишний вес/грязные диффы | P0 |
| Ад-хок скрипт с персональными путями в дереве пакета | `QSP.sublime-package/test_tce.py` | Не воспроизводим, вводит в заблуждение как «тест» | P1 |
| Конфиги ST в неудобном для поддержки виде (минифицированный JSON) | `Default.sublime-commands` | Сложно ревьюить/править, выше риск ошибок при редактировании | P2 |

### 2.2 Мёртвый/отладочный/незавершённый код
| Проблема | Где | Влияние | Приоритет |
|---|---|---|---|
| Отладочная функция `foo()` в конце модуля | `QSP.py` | Мёртвый код, захламляет API модуля | P1 |
| Большой закомментированный блок логики анализатора | `QSP.py` (`QspAnalyzerCommand.run`) | Шум, неясный статус фичи | P1 |
| Команда/класс-опечатка не используется | `QSP.py` (`QspHideHightlight`) | Путаница, дублирование намерений | P1 |
| Заглушки команд без функционала | `QspAnalyzerCommand`, `QspReplicStructCommand` в `QSP.py` | Белое пятно UX: команды есть, результата нет/минимальный | P2 |
| Экспериментальный модуль без интеграции | `qSpy/analyser.py` | Непонятная зрелость, риск «мертвого» роста | P2 |

### 2.3 Надёжность и интеграции (из кода/наблюдений)
| Проблема | Где | Влияние | Приоритет |
|---|---|---|---|
| Внешний конвертер: слабая обработка запуска процесса (stdout/stderr/returncode, риск блокировок) | `qSpy/converter/converters.py` (`QspsToQspOuterConv`) — также зафиксировано в `todo.md` | Молчаливые ошибки сборки, сложная диагностика | P1 |
| Потенциальные несоответствия имён команд/регистраций/ожиданий UI | `QSP.py`, `Default.sublime-*`, `Main.sublime-menu` | Команды могут быть недоступны/неочевидны | P1 (проверка), P2 (правки) |
| Платформозависимые дефолты/пути | `qSpy/const.py` (`PLAYER_PATH`), запуск процессов | Ограничения на non-Windows | P2 |
| Повреждённые/нечитаемые строковые литералы (mojibake кириллицы в среде аудита) | `qSpy/const.py`, `qSpy/function.py` | Битые подсказки/сообщения в UI, проблемы локализации | P1 (верификация и фиксация корректной кодировки) |

### 2.4 Сложность и техдолг ядра
| Проблема | Где | Влияние | Приоритет |
|---|---|---|---|
| Высокая сложность жизненного цикла workspace/кэша (реестр окон, identity/scope, v2 cache, index, prune, дебаунс) | `qSpy/workspace.py`, обработчики в `QSP.py` | Риск регрессий при правках, сложность отладки | P1 (осторожные точечные улучшения) / P2 (структурный рефакторинг) |
| Typing/линтер-долг (касты, `Any`, опциональные доступы) — частично уже в `todo.md` | `qSpy/workspace.py`, `qSpy/vars_scanner.py` и др. | Снижение пользы статанализа, скрытые ошибки | P2 |
| Дубли/разнобой сценариев построения и валидации проекта | `qSpy/project.py`, `qSpy/builder.py` | Сложность поддержки режимов (quick build, проект, одиночный файл) | P2 |

### 2.5 Тестирование и воспроизводимость
| Проблема | Где | Влияние | Приоритет |
|---|---|---|---|
| Нет единого набора автоматических тестов ядра (кроме syntax tests ST) | репозиторий | Регрессии логики конвертера/билдера/WS ловятся вручную | P2 |
| Существующие syntax tests — актив, но покрытие логики плагина не заменяют | `syntax_test_*` | Ограниченная защита от регрессий | P2 (расширять по мере правок) |

## 4. Риски и меры
- **Регрессии workspace/кэша:** менять инкрементально, тестировать на реальных проектах и «пустых» окнах; сохранять совместимость формата кэша или версионировать.
- **Поведение билда/конвертера:** внешние инструменты и пути пользователей различаются; изменения делать обратно совместимыми.
- **Кодировки/локализация строк:** правки UI-текстов проверять визуально в Sublime Text.
- **Случайное удаление нужного:** перед удалением «мёртвого» кода сверять использование поиском по репозиторию и регистрациям команд/событий.

## 6. Определение готовности (DoD) для каждого инкремента
- Изменения ограничены заявленной областью; нет непреднамеренных правок форматирования/кодировки в несвязанных файлах.
- Плагин загружается в Sublime Text, ключевые команды (build/run/convert/split, подсветки/кэш-команды из меню и палитры) работают на smoke-сценариях.
- Для затронутой логики добавлено/обновлено описание проверки (ручной сценарий или тест, если применимо).
- `todo.md`/`handoff.md` обновлены, если инкремент закрывает или уточняет известный пункт.
